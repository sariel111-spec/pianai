# dear us. · 偏爱馆藏

双主题的私人双人档案与作品收藏网站。切换李怀安与加菲版彼得时，整套布局、材质、标题、对话、封面与阅读页都会变化。适配桌面与手机，原生 HTML/CSS/JavaScript，无构建依赖，可部署到自己的 GitHub Pages。

## 两套独立设计

- **怀安笺 / 李怀安（《逐玉》）**：宣纸米色、苔玉绿、少量朱砂印记；卷首页、拱形肖像、竖排丹青封面、笺纸对话与故事卷。
- **The Parker Roll / 加菲版彼得·帕克**：墨蓝城市感、灰白底片纸、克制的砖红细节；电影片头、微倾拍立得双人档案、纽约胶片封面、英文衬线标题与聊天气泡。

顶部可直接切换二人。编辑双人档案中也可以选择每个关系使用的页面主题。所有关系的文字、头像与收藏各自独立。角色剧照仅作默认参考，来源见 ATTRIBUTION.md；你可以在编辑档案中替换。梦女信息未擅自填写。

## 双人档案主页

- 梦女 / 梦角独立头像，支持上传图片或填写链接。
- 二人名字、英文小标题与各自基本信息；基本信息每行使用「项目：内容」，可自由增加身份、生日、身高、性格、爱好等。
- 双人寄语、关系关键词、主页简介。
- 对话形式的相处模式：每行「我：内容」「你：内容」或「名字：内容」。支持修改标题和关系说明。
- 多梦向关系单独切换，每组关系拥有自己的头像、档案、对话与全部收藏。
- 主页下方展示最近稿件和故事入口。

## 四个收藏栏目

### 稿件整理

按归档日期排序，支持图片网格 / 列表；每篇可多图，附文案、画师、授权范围、分类、标签、来源与备注。支持年份和分类筛选、全文搜索、分页、图片阅读。

### 我们的故事

每篇有独立大标题、长文阅读页、故事发生日期、自由填写的时间线说明和章节序号。支持：

- 日期正序 / 倒序，或自定义章节顺序；发生日期和自定义顺序是两个独立字段。
- 在故事列表中拖放卡片改变章节顺序；也提供上移 / 下移按钮供触屏与键盘使用。
- 年份筛选、分类筛选、全文搜索（包括校对后的图片识别文字）。
- 快速翻阅滑条：定位全部筛选结果中的任意故事，自动切换到所在页并标记目标。
- 每页最多 12 篇卡片，避免把历年故事一次性全部挂在页面上。
- 多图故事，自动 OCR、单图重识别、图片顺序调整和识别文本校对。
- 正文与图片文字分别计数。字数指 Unicode 字符数：不含空白，包含标点。合计为正文加各图文本，重复内容不自动去重；OCR 不是准确字数保证。

### 梦向建设灵感

瀑布流式收藏，支持图片、想法、来源、标签与分类；建设进度可选待建设、构思中、已采用、已归档。

### 聊天记录

支持多张聊天截图、OCR、手动对话文本、TXT 导入与来源背景备注。对话文本每行「名字：内容」，以气泡排版呈现。无法自动恢复聊天截图中的人物归属；OCR 原文保存在图片下，需要自己校对、整理到正文后才能准确呈现左右对话。

没有恋爱日记、心动时间线、平行世界、心愿清单模块。

## 图片与 OCR

图片支持 PNG、JPEG、WebP，每张原图不超过 15 MB，每次最多导入 20 张。保存前以 JPEG（质量 .92）压缩，最长边最多 2400px；透明背景变为白色。导出的备份包含处理后的图片，不包含上传前的原始文件。若需要无损原稿，请另外保留原文件。

故事和聊天默认勾选自动识别。支持简体中文 / 繁体中文 / 英文 / 韩文，识别成功后显示置信度与字数，文字可人工修改。失败、取消或超时不会丢弃已经导入的图片，可重试或手动录入。

使用 Tesseract.js 5.1.1，浏览器内进行识别，无需 API 密钥。首次识别需要访问 jsDelivr 下载脚本、worker、WASM 与语言包；之后是否可离线取决于浏览器缓存。网络限制、设备性能、低清图、艺术字、竖排或复杂聊天背景可能导致下载失败或识别不准。图片不会由本应用上传到识别服务器。字体和占位封面不请求外部资源；你自己填写的远程图片会访问相应图床。

官方 API：https://github.com/naptha/tesseract.js/blob/master/docs/api.md

## 数据保存与备份

- 使用 IndexedDB 保存当前浏览器的完整馆藏，数据库 `dear-us-archive`。不需要部署服务器或数据库。
- 没有登录、密码加密、多人协作或自动跨设备同步。清除站点数据、换浏览器或换网址会影响数据可见性。
- 定期在「备份与设置」导出 JSON，换设备后再导入。导入会替换全部现有数据，不能合并。
- 浏览器存储仍有配额，存储不开放时网站只供查看；保存失败时会提示，原数据保持不变。
- 原版 `affection-archive-v1` 数据在同一地址首次打开新版时会尝试迁移：稿件转入稿件，信件转入故事，其他旧记录以及旧关系设定随备份保留，不再作为功能栏目展示。也可导入旧版备份。
- 首次展示的封面由本网站 CSS 绘制，是示例排版，不是你的真实稿件；所有示例可清空，编辑保存后的内容不再标记为示例。
- 请不要将私人备份 JSON 上传到公开 GitHub 仓库。

## GitHub Pages 部署

1. 解压后，把目录里的 `index.html`、`style.css`、`app.js`、`.nojekyll` 上传到你的仓库根目录。保留这些文件的相对位置。
2. 仓库 Settings → Pages → Build and deployment，选择 Deploy from a branch，再选择实际上传的分支（通常为 main），目录选择 `/ (root)`，保存。
3. 等部署完成后，使用 Pages 显示的网址访问。是否支持私有仓库部署取决于 GitHub 账户和设置。

也提供 `.github/workflows/pages.yml`：想使用该文件时，将 Pages Source 改为 GitHub Actions，然后手动运行 Deploy Pages。两种方法选择一种即可。

正式使用建议固定在 Pages 地址。直接打开 `index.html` 也可查看，但本地 file 协议下 IndexedDB 和 OCR worker 的可用性因浏览器而异。

## 验证与限制

运行 `node --check app.js` 和 `node checks.cjs`。逻辑检查覆盖主页、四个栏目、阅读与编辑表单、1,003 篇故事的分页与滑条、搜索、年份筛选、顺序调整、旧版迁移及失败保存回滚。

此次环境未提供可用浏览器 QA，未实测浏览器视觉与真实 OCR 识别结果。对话中的预览使用独立的内存数据，刷新后不保留，不运行 OCR；实际源码包含完整本地存储与 OCR 接入。
